# 卡片撰写规范（开放素材 · framework 型）

> 这份规范是**给写卡的人/Agent 看的契约**，不是给使用者看的广告。
> 它存在的理由：rulai-distill 的价值不在"写得好看"，而在**声称能被机器复核**。
> 一张卡只要有一处假声称（假引语、假段号、假"已被 X 核查确认"），整张卡的可信度归零——
> 见缺陷台账 #42 / #66 / #72 / #73：它们全是这类病。

## 0. 三条红线（违反即废卡）

1. **不许用卡片之外的知识补断言。** 卡片里每一条实质论断，都要能在
   `source_locator` 指向的语料里找到落点，或明确标为 `[通法]` / `[本卡规则]`。
   "我觉得《論語》大概也支持 X" 这种句子不许出现。
2. **引语必须逐字。** 逐字抄自 anchored 语料的**原字形**（公版典籍多为繁体，不许擅自转简），
   省略必须用 `…`，不许为了通顺改字。这条不是学究气：`anchor`/`verify-quotes` 是**按字机器核验**的，
   改一个字就从"可核"变成"不可核"。
3. **不许安一个不存在的核验者。** 禁止在卡片正文写「评分 Agent 核查确认」「XX 已验证」——
   核查记录属于质检环节，写在 `FIDELITY.json` / 审计报告里，不写在卡片里（#72/#73）。
   唯一允许的措辞是「建卡时对 anchored 语料全库检索确认（可机械复算）」，且必须给出可复跑的命令。

## 1. frontmatter 字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | ✅ | slug，小写字母 + 连字符，与目录同名 |
| `title` | ✅ | 中文标题：`书名原文 · 一句话定位` |
| `description` | ✅ | 多行，写清**适用 / 不做 / 不用于**三段，并明确边界 |
| `source_material` | ✅ | 素材名字 + 出处（含公有领域说明） |
| `source_locator` | ✅ | `语料路径 + 具体段号列表`（一张卡的引语段号要列全） |
| `material_type` | ✅ | `book` / `video` / `person` / `podcast` |
| `capability_type` | ✅ | `framework` |
| `tags` | ✅ | ≥4 个，**会被 `eval-kit utility` 用作"专有元素"信号**——写宽泛词（思维/方法）会失效 |
| `related_skills.contrasts_with` | ✅ | ≥2 张邻近卡 slug，并在 A2/B 里真的做了区分 |
| `promotion` | ✅ | `promoted` |
| `extractor` | ✅ | `framework` |
| `verification` | ✅ | `source_sufficiency` / `executability` / `task_utility` 三项，均为 `pass` |

## 2. 章节结构（顺序不许变）

```
# 标题
> 一句话定位（这套方法把 X 从 Y 变成 Z）
> 注：引语逐字原字形；注2：source_locator 指向蒸馏工作区语料，语料不随技能发布

## R — Reading（原文锚点）          ← ≥8 条带段号引语，每条附一句"为什么会选它"
## I — Interpretation（方法论骨架）    ← 因果链（编号，不是要点罗列）+ 适用前提 + 关键心法
## 来源状态                          ← 每条论断标 [原文] / [通法] / [本卡规则]（见 §3）
## A1 — Past（原书自身的应用与演示）   ← 必须含「诚实说明」：素材里到底有没有这类内容（次数
                                        是多少就写多少），没有就不能编例
## A2 — Future（何时需要它）            ← 触发情境 + 语言信号 + 与邻近能力区分表 + 关键分界
## E — Execution（可执行步骤）          ← 3 分钟版（≤3 步，必须有明确输出形态）+ 完整版（Step1..N，
                                        每步含 做什么/完成标准/⏸️ 检查点）
## B — Boundary（边界与失败模式）       ← 不适用清单 + 失败模式表（症状/根因/纠正）+ 易混淆辨析
```

**每一步 Step 都要有 ⏸️ 检查点**——这是真方法与 PPT 的区别：
检查点的作用是"走到这儿卡住时该怎么处理"，不是装饰。

**3 分钟版的输出必须是可判的形态**（三选一 / 二元 / 带阈值），
"视情况而定"和没有截止日的"再看看"都**不是合法输出**（这是本项目的硬规矩）。

## 3. 来源状态区块（#75 起为可选但推荐）

三类标签，每条论断一行：

```markdown
- [原文] 观过比听言更准：四之七「人之過也，各於其黨。觀過，斯知仁矣。」
- [通法] 识人必须落到行为对照（原文依据 …，"必须对照"是推演）
- [本卡规则] 输出必须三选一，原文无此要求——本卡自定的操作约束
```

- `[原文]`：逐字来自素材，**必须带段号**（可机器复核）
- `[通法]`：素材精神的方法论推演，**必须写出原文依据**，且说明哪一步是推演
- `[本卡规则]`：卡片自加的操作约束，**必须明说原文没有这条**

声明了区块就必须**逐条标注**：缺标签或自造标签 → `validate` **error**；不声明 → warn（不卡发布）。
→ 这是 #72/#73 的机制化收口：**让读者能分清"哪句是原文、哪句是推演、哪句是卡片自己立的规矩"**。

## 4. 引语格式（书类素材）

anchored 语料是 `【第N段】` 形式，卡片侧写法：

```markdown
> 「巧言令色，鮮矣仁。」
> —— 话说得漂亮、脸色讨喜，与"仁"负相关
> —— 《論語》一之三          ← 段号/篇-章号，必须是 anchor 认的形状
```

`td.py anchor` 认三种段号标记：`§N`、`【第N段】/【第N条】`、也可以是篇-章号（`一之三`，语料里独占一行的标签）。
**写法以通得过 `anchor` 为准**——写完好不好看不重要，能不能复核才重要。

## 5. 自验（写完必跑，且要报告实跑输出）

在仓库根目录执行（**必须用托管 Python**，`/usr/bin/python3` 是 3.9 会假失败）：

```bash
PY=/Users/yihe/.workbuddy/binaries/python/versions/3.13.12/bin/python3
cd /Users/yihe/WorkBuddy/2026-10-03-12-20-21/rulai-distill

$PY scripts/td.py validate examples/open-bundle                    # 必须 error 0
$PY scripts/td.py anchor  <你的卡片路径>/SKILL.md --corpus <语料路径>  # 必须 0 挂错
$PY scripts/td.py lint-quotes <你的卡片路径>/SKILL.md                # 干净
$PY scripts/td.py output-eval <你的卡片路径>/SKILL.md                # 通过
$PY scripts/td.py eval-kit init <你的卡片路径>/SKILL.md --out <套件目录>
```

`anchor` 的三态判定要知道：**FAIL / PASS / UNVERIFIED**——
"有引语但 0 条可核验"是 **UNVERIFIED**（退出码非 0），**不是通过**。
如果 `anchor` 报 UNVERIFIED，说明你的段号标记形状不对，改到通过为止。

## 6. 还要写 SOURCES.md

卡片同级必须有 `SOURCES.md`：取源页面 URL、抓取日期、清洗方式、完整性自检、
以及**"哪些内容这张卡明确不覆盖"**。语料本身不随技能发布，`SOURCES.md` 就是读者唯一的溯源头。

---

**最后一句**：这张卡会被另一品牌 Agent 拿去答题、还会被跟"没有这张卡"的答案对照。
它真正要赢的不是"写得好"，而是**用了它的人做出来的东西，跟没用它的人不一样，且那个不一样能被机器测出来**。
