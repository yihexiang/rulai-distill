# 长书 token 节省实测

> 由 `benchmarks/token-savings/measure.py` 生成。方法与脚本同源，**每个数字都可复跑**。

## 《rulai-distill/corpus/anchored/src-01-tongjian-wei.md》

| 项 | 值 |
|---|---|
| sha256 | `0fc6d60fba710d166780bb84f40baa593946c7a4fe1e5c106e595ca698856d72` |
| 全书字符 | 107,120 |
| 分块数（`index --grep` 的返回单元） | 212 |

| 关键词 | 命中块 | 整本 | 窗口(命中块) | 窗口(+邻块) | 索引+读1块 |
|---|---:|---:|---:|---:|---:|
| 威烈王 | 3/212 | 155,299 | 5,231 / 29.69× | 8,642 / 17.97× | 8,770 / **17.71×** |
| 安王 | 27/212 | 155,299 | 5,863 / 26.49× | 10,910 / 14.23× | 8,765 / **17.72×** |
| 烈王 | 16/212 | 155,299 | 10,455 / 14.85× | 17,448 / 8.9× | 8,767 / **17.71×** |
| 校刊記 | 5/212 | 155,299 | 1,041 / 149.18× | 7,127 / 21.79× | 8,815 / **17.62×** |


**本书记法能省多少**

- **窗口（只读命中块）**：整本的 **1/149.18 ～ 1/14.85**（14.85× ～ 149.18×）
- **窗口（+邻块，现实口径）**：整本的 **1/21.79 ～ 1/8.90**（8.90× ～ 21.79×）
- **索引 → 定点读 1 块**：整本的 **1/17.72 ～ 1/17.62**（17.62× ～ 17.72×）

- 最诚实的那一端（烈王，命中 16/212 块）：**只省 8.9×**。关键词一宽，「检索」就退化成「通读」——**这是分块的真实上限，不是意外**。
- 最好的一端（校刊記，命中 5/212 块）：21.79×。

## 结论区间（跨书）

- **读全部命中块**：整本的 **1/14.85 ～ 1/149.18**
- **命中块 + 邻块（现实口径）**：整本的 **1/21.79 ～ 1/8.90**
- **索引 → 定点读 1 块**：整本的 **1/17.72 ～ 1/17.62**

**这些区间的下端不是噪声，是结论**：书越短、关键词越宽，分块越省不下东西——**短书上分块几乎没有收益**（下端那些1.0× 附近的样本就是这种情况）。所以「用分块处理长书」这句话的适用条件是**书足够长 ∧ 你知道自己在找什么**，两条缺一不可。

## 不可外推声明

1. 只测了 1 本书（见各书 sha256），换书会变——**区间下端来自短书/宽词，不是所有书都能省到那么多**
2. 节省倍数**主要由两件事决定**：书有多长、关键词有多具体。书短或词宽时几乎不省（本次实测下端就在 1.0× 附近）。单点数字没有意义
3. window 类模式假设关键词能定位到正确的块。关键词选不准时，省下的 token 会以「读错块」的形式还回去——**省 token 与读对内容是两件事**
4. index_then_read 只读了 1 块，覆盖面最窄；它最省，但最可能不够用
5. 只算文本 token，不含工具调用、Agent 系统提示、图片 / 音频转写
6. tiktoken 是 OpenAI 的编码（cl100k_base）；别的厂商绝对值不同、比例关系大体成立

## 复跑

```bash
python3 -m venv <dir> && <dir>/bin/pip install tiktoken
<dir>/bin/python benchmarks/token-savings/measure.py \
  --corpus <书1> --corpus <书2> --sweep
# 换书后内置词可能全不命中；脚本会自动从该书章节标题取词，
# 也可显式指定：--sweep-auto
```

没装 `tiktoken` 时脚本**明确报「未运行」并以退出码 2 结束**，不会用字数估算冒充 token 数。
