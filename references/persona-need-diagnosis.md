# 人物蒸馏 · 模糊需求诊断分支（可选）

> 来源：nuwa-skill 的 Phase 0B（需求诊断）+ Phase 0A（档位确认），经 rulai 离线优先改造后**补回**为可选分支。
> 适用：用户输入的是**模糊需求/困惑**（「我想提升决策质量」「有没有一种思维方式能帮我看透商业本质」），而不是明确人名。
> 不适用：用户已给明确人名 → 直接走 SKILL.md §人物蒸馏分支的六路调研。
> 本分支是**推理密集型**流程，由 Agent 按本文档执行；脚本只提供六路调研骨架（`td.py research init`），不替代诊断判断。

## 为什么需要这个分支

人物蒸馏的价值不在「复制名人」，而在「给用户一个能拓展其思维边界的认知透镜」。但多数用户来的时候只有困惑、没有目标人物。强行让他指定一个人，往往得到错配。这一分支把「从需求反推最合适的蒸馏对象」显式化，避免两种失败：

- 用户说「提升决策质量」，Agent 却去蒸馏了一个表达型人物（维度错配）；
- Agent 二话不说直接蒸馏一个用户根本不感兴趣的人，浪费一轮重调研。

## Step 1 · 需求定位（≤2 轮追问）

通过 1-2 个追问，定位核心需求维度。追问原则：

- 最多 2 轮，不要变成问卷；
- 用户已表达清晰就不追问，直接推荐；
- 追问目的是区分相近维度（如「决策」是商业决策还是人生方向？）。

### 需求维度表

| 需求维度 | 典型表达 | 思维框架方向 | 推荐蒸馏对象类型 |
|---|---|---|---|
| 决策与判断 | 「怎么做更好的决策」「总是选错」 | 多元思维模型、逆向思考、概率思维 | 投资者 / 企业家 / 军事策略家 |
| 表达与写作 | 「想把复杂的事说清楚」「文章没人看」 | 费曼式简化、故事化、类比 | 科普作家 / 演讲家 |
| 创业与商业 | 「想做独立开发」「找不到 PMF」 | 第一性原理、杠杆、产品克制 | 连续创业者 / 产品人 |
| 教学与传播 | 「讲课没人听」「知识传递效率低」 | 从已知到未知、隐喻、最少必要 | 教育家 / 认知科学家 |
| 批判思维 | 「总被忽悠」「看不透本质」 | 证伪、演化论视角、偏差识别 | 科学家 / 哲学家 |
| 内容创作 | 「做视频没流量」「内容没特色」 | 注意力工程、测试迭代、受众心理 | 创作者 / 增长黑客 |
| 人生策略 | 「职业迷茫」「时间总不够」 | 长期主义、杠杆选择、复利 | 通才型思想家 |
| 风险与不确定性 | 「应对黑天鹅」「投资总亏」 | 反脆弱、凸性、尾部风险 | 期权交易者 / 风险学者 |
| 设计与产品 | 「用户体验差」「不会做减法」 | 极简、用户心理模型、约束即创意 | 设计师 / 产品哲学家 |
| 幽默与表达力 | 「说话没意思」「想更有趣」 | 荒诞对比、预期违背、自嘲 | 喜剧演员 / 脱口秀 |

## Step 2 · 候选推荐（2-3 个）

先判断**人物 Skill 还是主题 Skill**：

- 需求指向某种具体思考方式 → **人物 Skill**（蒸馏某人的思维框架）。
- 需求指向某领域方法论 → **主题 Skill**（综合多人视角；走六路调研但按「流派」分而非按「人」分）。
- 不确定 → 两类都给，让用户选。

候选展示格式（每个）：

```
### 候选 N: [人名/主题]  ⚡已有 Skill / 🆕需蒸馏
**核心镜片**：此人看世界的独特方式，一句话
**为什么适合你**：直接对应用户需求，说清匹配逻辑（这个人的哪个思维模型解决用户的哪个具体问题）
**局限**：这个视角的盲区，什么问题帮不了
```

推荐原则：≤3 候选（选择困难比没选择更糟）、已有 Skill 优先（即插即用零成本）、候选间要有差异、必须说清局限（没有万能思维框架）。

## Step 3 · 用户选择 → 进入蒸馏

- 选已有 Skill → 直接激活，任务完成。
- 选新蒸馏候选 → 进入 SKILL.md §人物蒸馏分支：六路调研（`td.py research init`→填 6 车道→`td.py research merge`）+ 认知植入卡（`templates/PERSONA.md.template`）。

## 成本档位（开跑前确认，避免长任务意外烧 token）

| 档位 | 调研规模 | 适用 |
|---|---|---|
| 快速 | 3 维度（著作+对话+表达），每维度≤5 来源 | 试效果 / 冷门人物 |
| 标准（默认） | 六路完整调研 | 大多数场景 |
| 深度 | 六路 + 一手素材全量下载 | 打算发布的精品 |

**rulai 离线优先改造（与 nuwa 的关键差异）**：nuwa 默认走网络搜索；rulai 默认**本地语料优先**——优先让用户丢一手素材（书籍 PDF / 字幕 / 转录稿），网络搜索仅在缺口维度启用，且 `td.py fetch-subtitle` 默认 dry-run。这把「编造风险」和「成本」都压到最低，也契合本技能「零网络」承诺（SKILL.md 边界声明 2）。

## 诚实边界

- 诊断推荐是**启发式**，不替代用户自己判断谁适合；
- 推荐的人物若公开信息极少（<10 条可用来源），必须降级并在候选卡片标注推测成分；
- 蒸馏在世非公众人物：必须由用户提供素材，并提醒征得当事人同意；
- 本分支**未经真实用户大规模验证**——它是从 nuwa 移植 + 离线改造的流程指南，落地时如发现某维度表错配，回写本文件并登记缺陷台账。
