# style-1 盲排对照样本 · wangyangming-xinxue

> 由 `td.py eval-kit init` 生成后人工补写（缺陷 #82 的修复产物）。
> style 维要测的是「盲辨：把三份回答混排，认出哪一份来自本卡」。
> 本文件提供**另外两份通用回答**，与答题 Agent 的答案一起构成三选一盲排。
> **辨识依据必须是具体的方法偏好（走哪几步、卡在哪、什么算完成），不是篇幅与排版。**

## 混排题目（三份回答回答的是同一道题）

> 一个人总在「想清楚再动手」和「先干起来再说」之间反复，长期停在想、落不了地。请就这个处境给出你的判断过程与结论。

## 通用回答样本 A（generic · 最佳实践口吻）

> 这种拖延本质上是过度准备。建议先接受一个「最小可行行动」：把任务拆成几天就能完成的小步，先做出第一个可见成果，再在反馈里迭代。
> 同时给自己设一个「思考截止线」，比如三天内必须动手，过了线就不再纠结方案完美度。关键是把「想」转化成「做」，靠行动来校准认知。

## 通用回答样本 B（generic · 结构化清单口吻）

> 可以分四步：1. 界定问题——到底卡在方案不确定还是怕失败；2. 列出待验证假设；3. 选一个成本最低的假设先试；4. 用结果反推要不要继续想。
> 每一步都给一个交付物，避免停在脑内推演。如果两周还没落地，就强制进入「先干」模式。

## 评分 Agent 的操作（盲排）

1. 把「答题 Agent 的答案 + 上面 A/B 两份」随机编号为 ①②③，抹掉一切来源标记；
2. 交给评分 Agent 辨认哪一份来自本卡，并要求写出**具体方法偏好依据**；
3. 认错 → style 该档从严；**没有做这一步就给 style 高分是假绿**，
   `scores.template.json` 的 style.note 必须写明「已盲排」或「未盲排（理由）」。
   > 本卡的辨识锚点（供评分参考，不预先透露给盲排）：强调「知而不行只是未知」——把"停在想"本身诊断为"还没真知"，
   > 而非时间管理问题；并要求以"良知/心"为判准，而非外部 KPI 或清单。
