# 阶段 1.5 · 三重验证

> 目的：把阶段 1 的候选池从"看起来像方法论"收敛到"真的能变成技能"。

## 三道关卡

### 关卡 1 · 来源充分性

问：原文是否有支撑？能否定位？

| 判定 | 条件 | 处理 |
|---|---|---|
| 通过 | 能定位到具体段落/章节/时间戳 | 记录 `source_evidence.location` |
| 通过（弱） | 单一来源但逻辑自洽完整 | 标记 `evidence_strength: single`，在 B 段注明 |
| 拒绝 | 只有二手转述，无法定位原文 | 移入 `candidates/UNVERIFIED.md`，不进入能力卡 |

**重要放宽规则**（来自 cangjie 的实践洞察）：

> 一个**完整讲透一次**的流程或公式即可通过来源验证。**不要求作者反复论述，也不要求是作者原创。**

这条规则很关键。传统的"需要 3 处以上佐证"会误杀大量优质单元——很多方法论作者一辈子只讲一次，但讲得非常完整。

### 关卡 2 · 可执行性

问：能不能转成"在什么场景下做什么"？

**通过标志**——必须能填出这三个空：
- [ ] 在【什么情境】下（具体场景，不是"面对问题"）
- [ ] 应该【做什么动作】（可观察的动词）
- [ ] 做到【什么程度】算完成（可判定的标准）

**不通过的典型**：
- "要善于思考" → 无动作、无完成标准
- "应该系统性地分析问题" → "系统性"不可观察
- "要关注长期价值" → 什么算关注了？

**不通过的正确处理**：不是丢弃，而是**降级为 I 段素材**。这类内容往往是指向某个真实方法论的入口，应记录到 `candidates/principles.md` 作为背景，**不要硬做成技能**。硬做出来的技能会在压力测试阶段全部失败。

### 关卡 3 · 任务效用

问：真实场景会用得上吗？

用**否定测试**（比肯定测试更有效）：

> "什么情况下，这个判断是错的？"
> "有没有人做这件事会得到相反的结论，而且他是对的？"

- 想不出反例 → 可能是废话
- 反例明显且原书也承认 → 边界清晰，**通过且 B 段素材充足**
- 反例明显但原书没说 → 通过，B 段标注"本书未讨论此边界"

**特别注意"听起来正确"陷阱**：绝大多数商业/管理方法论都能通过"说得有道理"检验，但无法通过"能否判定完成"检验。关卡 2 和 3 一起用才能拦住它们。

## 验证记录

每个单元记录：

```yaml
- candidate: 能力单元名
  source_evidence:
    location: 卷3 / 矛盾论 / 1937.08   # 精确定位
    evidence_strength: strong|weak|single
  executability:
    situation: 多重问题纠缠不清时
    action: 列出所有矛盾 → 识别主要矛盾 → 判断主要方面
    completion_criterion: 产出一条"解决了它其他问题会自动变轻"的判断
    status: pass|fail
  utility:
    counter_case: 单一问题场景下无主要矛盾可识别
    boundary_source: B-段（作者原文警告）
    status: pass|fail
  verdict: promoted_candidate | downgraded_to_background | rejected
  reject_reason: 不可执行（无完成标准） | 无反例（疑似废话） | 来源不可定位
```

## 产出

- 通过 → `capabilities/` 候选池，进入阶段 2
- 降级 → `candidates/background.md`（**不要删**，它是 I 段的素材库）
- 拒绝 → `candidates/REJECTED.md`（记录原因，避免重复劳动）

**保留拒绝记录的价值**：一轮蒸馏后，复盘拒绝清单能识别出"整本书不适合蒸馏"的信号（如全是背景叙述），比逐个修复更高效。
