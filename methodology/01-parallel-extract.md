# 阶段 1 · 五路并行提取

> 目标：把长内容切成五条独立视角并行扫描，各自产出候选单元池。
> 关键设计：**并行分发**——五个提取器应分发给不同 Agent 同时跑，而非一个 Agent 顺序执行（顺序执行会产生确认偏误，第四个提取器会向第三个的结论靠拢）。

## 为什么要并行

单 Agent 顺序读完五个维度，等于让它在同一份上下文里反复切换角色。实测后果：

- 提取 `principles` 时会被前面读到的 `frameworks` 框架化（把框架包装成原则）
- 提取 `counter-examples` 时因为已经理解框架，难以察觉框架的漏洞
- 产出高度同质，五个池子互相污染

**并行是机制设计，不是性能优化。**

## 分发指令

对每个提取器，给子 Agent 相同的输入（全书分块内容 + 阶段 0 结论），不同的角色定义。**不要给提取器看其他提取器的产出**——隔离是全部价值所在。

| 提取器 | 角色定义（分发给子 Agent 的 prompt 要点） | 产出文件 |
|---|---|---|
| 框架提取器 | 找出作者反复使用的**结构化思考工具**（有槽位、有步骤、有变量） | `candidates/frameworks.md` |
| 原则提取器 | 找出**带条件的判断规则**（"当…时，应该…"，而非"要重视…"） | `candidates/principles.md` |
| 案例提取器 | 找出**可类比的具体情境**（时间、主体、动作、结果） | `candidates/cases.md` |
| 反例提取器 | 找出**作者明确警告的失败用法**，以及隐含的反面推论 | `candidates/counter-examples.md` |
| 术语提取器 | 找出**专有名词与语境特定义**（不是词典定义，是"在这本书里指什么"） | `candidates/glossary.md` |

### 框架 vs 原则的区分（最容易混的一对）

- 框架：**有槽位的结构**。"SWOT 四格"「机会/威胁/优势/劣势」——填空题
- 原则：**有条件的判断**。"当增长快于现金流时，优先解决账期"——决策题

判据：**能不能画成图？** 能画成填空结构的是框架，只能写成"如果…那么…"的是原则。

### 素材是人物时

额外第六个提取器：`extractors/persona-extractor.md`，专门提取认知植入所需素材（信念来源、关键决策、失败、矛盾）。

**不要**用五路提取器处理人物素材——人物的"方法论"通常尚未成型，强行提取会得到二手转述的二手转述。

## 提取记录格式

```markdown
## <能力单元名>

**定位**: 卷X / 章节名 / 段落起始句
**原文摘录**: "> 关键句（不超过 50 字）"
**提取类型**: framework | principle | case | counter-example | glossary
**强��度**: strong（多处论述） | single（单次但完整）
**初步可执行性**: 可执行 / 需转化 / 纯观点
**初判**: 通过三重验证 / 疑似背景 / 疑似废话
```

**"原文摘录"必填且不超过 50 字**。限制长度会强制提取者真正读懂，而不是整段复制。超过 50 字说明还没提炼出核心，应重写。

## 完成判据

进入阶段 1.5 前确认：

- [ ] 五个池子都有产出（某池为空说明该维度确实没有，不是提取失败）
- [ ] 每个候选都有原文摘录 + 定位
- [ ] 框架池和原则池没有明显重复
- [ ] 候选总数与内容体量匹配（190 万字产出 200-400 候选是正常量级；产出 5 个说明提取器没认真跑）

## 数量异常的处理

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 候选 < 20 | 提取器没认真跑，或内容体量确实小 | 换 Agent 重跑，确认不是漏读 |
| 候选 > 800 | 未执行三重验证就堆砌 | 正常，靠阶段 1.5 收敛 |
| 五个池子内容高度相似 | 用了同一个 Agent 顺序执行 | 必须改为并行分发 |
